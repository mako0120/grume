# グルメ専用Gmail 最安定運用ルール

このGmailは **グルメCanva制作依頼の投入口専用** とする。

公開用問い合わせ窓口、PR営業、私用メール、各種サービス登録には使わない。

目的は、ChatGPT Automationが対象メールを迷わず検知し、写真解析 → Web調査 → MD作成 → Canva制作 → 保存 → GitHub記録まで安定して実行できる状態を保つこと。

---

## 1. Gmailの役割

専用Gmailは次の用途だけに使う。

- Canva投稿を作りたい店舗の写真を受け取る
- 店舗名 / コース名 / 料理名 / メモを受け取る
- ChatGPT Automationが新規案件を検知する
- 完成通知を受け取る

次には使わない。

- PR企業との通常連絡
- 求人 / 学校 / 私用
- メルマガ
- ECサイト登録
- SNSログイン
- その他の自動通知

**受信箱に入るメールのほぼ全てが制作依頼** という状態を維持する。

---

## 2. 1メール = 1店舗・1撮影案件

1通のメールに複数店舗を混ぜない。

同じ店舗でも撮影日やコースが違う場合は別メールにする。

例:

- 9/28 焼肉しょうちゃん天満 粋コース → 1案件
- 10/10 焼肉しょうちゃん天満 別コース → 別案件

これにより、写真・料理名・Canva・MDの混在を防ぐ。

---

## 3. 件名を固定する

必須形式:

```text
[グルメCanva][YYYYMMDD-連番] 店舗名
```

例:

```text
[グルメCanva][20260928-01] 焼肉しょうちゃん天満
```

同日に2店舗目なら:

```text
[グルメCanva][20260928-02] うどん和匠
```

### 理由

- `[グルメCanva]` で自動検知できる
- 日付 + 連番で同名店舗の重複処理を防げる
- Gmailのスレッド統合事故を減らせる
- GitHub保存先と一致させやすい

---

## 4. 本文テンプレート

推奨形式:

```text
店舗名：焼肉しょうちゃん天満
エリア：天満
コース：粋コース

料理：
・キムチ盛り合わせ
・和風ナムル
・和牛炙りユッケ
・厚切りタンブリアン
・チシャ
・厳選赤身2種
・厳選ホルモン2種
・豪快特上ハラミ
・こだわり和風冷麺

メモ：
・タンとハラミを強めに推したい
・厚切りタンが特に美味しかった
・PR案件
```

### 必須

最低限どちらかを必ず入れる。

- 件名に店舗名
- 本文に `店舗名：`

### 任意

分かる場合だけ書く。

- エリア
- コース
- 料理順
- 実際に食べて感じたこと
- 特に推したい料理
- PR条件

分からない情報は空欄でよい。AI側でWeb調査する。

---

## 5. 写真ルール

### 推奨枚数

```text
8〜20枚
```

原則20枚以内。

20枚を超える場合は、投稿に使いたい写真を先に20枚以内へ絞る。

### 写真の種類

可能なら次を含める。

- 外観
- 店内
- 乾杯 / ドリンク
- 各料理
- 焼いている様子
- 箸上げ / 断面 / アップ
- 締め料理

### 送信順

写真の送信順は投稿順でなくてよい。

本文に料理順が書かれている場合、料理順を優先してAIが並べ替える。

### 避けるもの

- 同じ写真の重複
- 極端なブレ
- スクリーンショット
- 他店舗の写真
- 動画
- Canva完成画像

1メール内は **その店舗の素材だけ** にする。

---

## 6. ユーザーの実食情報とWeb情報を分ける

本文の `メモ：` に書かれた内容は、ユーザー自身の実食情報として扱える。

例:

```text
・タンが特に美味しかった
・肉うどんはボリュームが多かった
・開店20分前から並んだ
```

一方、Webの口コミに書かれている感想をユーザーの体験として書かない。

---

## 7. Gmailラベル

専用Gmailでは以下のラベルを使う。

```text
GRUME/NEW
GRUME/PROCESSING
GRUME/REVIEW
GRUME/DONE
GRUME/ERROR
```

### NEW

新規依頼。

### PROCESSING

ChatGPTが現在処理中。

### REVIEW

料理名や写真対応などに要確認事項がある。

### DONE

Canva保存・GitHub記録まで完了。

### ERROR

処理に失敗し、再実行または確認が必要。

---

## 8. ステータス遷移

正常:

```text
NEW
 ↓
PROCESSING
 ↓
DONE
```

要確認:

```text
NEW
 ↓
PROCESSING
 ↓
REVIEW
```

失敗:

```text
NEW
 ↓
PROCESSING
 ↓
ERROR
```

DONEのメールは再処理しない。

---

## 9. ChatGPT Automationの検知条件

対象:

```text
件名に [グルメCanva]
画像添付あり
DONEではない
PROCESSINGではない
```

専用Gmailなので、通常メールを大量に検索する必要はない。

対象メールがなければ何もしない。

---

## 10. Web調査

メールを検知したら店舗名を使ってWeb検索する。

優先順位:

1. 公式サイト
2. 公式Instagram
3. 運営会社公式
4. Google店舗情報
5. 食べログ
6. その他信頼できるグルメ媒体

確認する内容:

- 正式店舗名
- エリア / 最寄駅
- コース名
- 料理名
- 店舗の特徴
- 名物
- 必要なら住所 / 営業時間 / 定休日 / 価格

未確認情報は断定しない。

---

## 11. MD作成

Web調査と写真解析のあと、まずMarkdownを完成させる。

MDがCanva制作の設計書になる。

保存先:

```text
posts/YYYY/MM/YYYY-MM-DD_店舗名/
  post.md
  record.md
```

`post.md`:

- 店舗情報
- 調査結果
- 表紙
- 写真順
- 各ページ料理名
- 各ページコピー
- 要確認事項

`record.md`:

- 案件ID
- 受信日
- Canva URL
- 使用テンプレート
- ステータス
- 完成日時

---

## 12. Canva制作

MD完成後にCanvaを作る。

基準:

- 焼肉 城と七宝
- 蟹かに城

共通:

- 1080 × 1350
- 既存フォント維持
- レイアウト維持
- ページ構成維持
- 写真と文章だけ差し替える
- MASTERを直接上書きしない
- 投稿ごとにコピーを作る

料理順がある場合はコース順を最優先。

写真と文章の不一致がある場合は保存完了扱いにしない。

---

## 13. Canva保存後

正常に保存できたら:

1. Canvaの編集URLを取得
2. GitHubに `post.md` 保存
3. GitHubに `record.md` 保存
4. `posts/INDEX.md` 更新
5. Gmailを `GRUME/DONE` にする
6. 完成通知を返信

返信例:

```text
グルメCanva制作が完了しました。

店舗：焼肉しょうちゃん天満
ステータス：完成

Canva：
https://www.canva.com/...

MD：
GitHub posts/2026/09/...
```

---

## 14. 要確認時

AIが以下を判断できない場合は勝手に断定しない。

- 料理名
- 肉の部位
- コース上の位置
- どの写真がどの料理か
- 店舗情報の食い違い

その場合:

```text
GRUME/REVIEW
```

にして、確認事項を明記する。

---

## 15. 失敗時

Canva編集、Web調査、写真処理などで失敗した場合:

- 完成扱いにしない
- `GRUME/ERROR` にする
- エラー内容を記録
- 同じ案件を無限再実行しない

---

## 16. 最も安定する日常運用

ユーザーが行うことは基本3つだけ。

### ① 撮影

店舗で写真を撮る。

### ② 専用Gmailへ送る

```text
件名:
[グルメCanva][20260928-01] 店舗名

本文:
店舗名 / コース / 料理 / メモ

添付:
投稿候補写真 最大20枚
```

### ③ 完成通知を待つ

ChatGPT Automation側で:

```text
検知
→ 写真解析
→ Web調査
→ MD
→ Canva
→ 保存
→ GitHub記録
→ Gmail返信
```

まで行う。

---

## 17. 運用上の禁止事項

安定性のため、次は避ける。

- 1メールに複数店舗
- 件名から `[グルメCanva]` を消す
- 途中で同じ案件を何度も送り直す
- 完成前に同じ件名で追送する
- 他店舗写真を混ぜる
- 味の感想をAIに推測させる
- MASTER Canvaを直接変更する

追加写真が必要な場合は、新規メールではなく明確に:

```text
[追加][20260928-01] 焼肉しょうちゃん天満
```

として案件IDを一致させる。

---

## 最終形

最も安定する構成:

```text
グルメ専用Gmail
      ↓
ChatGPT Automation
      ↓
Web調査
      ↓
MD
   ↙     ↘
GitHub   Canva
          ↓
       自動保存
          ↓
     Gmail完成通知
```

専用Gmailは **入口**、ChatGPTは **実行主体**、Canvaは **完成物**、GitHubは **ルール・MD・履歴の正本** とする。

## 18. 写真が10枚を超える場合（モバイル運用）

iPhone / Gmailアプリでは一度に送れる写真数に制約が出る場合があるため、**複数メールに分割して送ってよい**。

### 推奨形式

案件ごとに共通の案件IDを付ける。

1通目:

```text
[グルメCanva][20260928-01][1/2] 銀蔵 小野原本店
```

2通目:

```text
[グルメCanva][20260928-01][2/2][完了] 銀蔵 小野原本店
```

3通に分ける場合:

```text
[グルメCanva][20260928-01][1/3] 店舗名
[グルメCanva][20260928-01][2/3] 店舗名
[グルメCanva][20260928-01][3/3][完了] 店舗名
```

### 重要

- 同じ案件は **同じ案件ID** を使う
- 最後のメールだけ `[完了]` を付ける
- `[完了]` が来るまではChatGPT AutomationはCanva制作を開始しない
- 同じ案件IDの本文・写真・Google Drive画像リンクは全て結合して1投稿として扱う
- 1通目に店舗情報・料理名・メモを書けば、2通目以降は「追加写真」のみでもよい
- 同じ写真を重複送信しない

### 例

1通目本文:

```text
店舗名：銀蔵 小野原本店
コース：銀蔵特選お造り定食
エリア：箕面

料理：
・銀蔵特選お造り定食
・天ぷら
・味噌汁

メモ：
・ボリュームが多い
・大トロが特に美味しかった
・えび刺身が大きかった
```

2通目本文:

```text
追加写真です
```

これで20枚前後でも、10枚ずつ2通に分けて安全に送れる。
